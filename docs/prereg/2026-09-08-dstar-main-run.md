# 运行记录:12 checkpoint × 64 outcome prompt × 4 draw

**2026-09-08 起草,在启动前。** 这不是新的科学预注册——
`docs/prereg/2026-09-06-decoupling-pilot.md` 的假设、终态与禁止事项**原样继承,不改写**。
本文只登记**规模是怎么定的**,以及为什么与试点不同。供 `run_manifest.json` 的
`protocol_sha256` 指向。

| | 试点 2026-09-06 | 本次 | 为什么 |
|---|---|---|---|
| rounds | 10 | **11** | 11 × 12 = 132,正好等于训练 prompt 数,顶到 `max_epochs=1` |

## 2. 规模是由检出力定的,不是由预算定的

`review-packets/outcome-budget-20260908/`。噪声不用二项模型,用试点自己的残差:
两臂 5 个 checkpoint,残差 SD 2.92 / 1.49 pt 对二项预测 6.1 pt,
合并 6 df 的 χ² = 0.87,**p = 0.010**。比值 0.38,95% CI [0.25, 0.84]。
原因是 `fixed_latents: true` 把 spec 难度差变成被配对消掉的固定效应。

12 个 checkpoint、折点前外部涨幅 0.10 时的检出力(300 试验/格):

| 噪声假设 | R=1 | R=2 | **R=4** |
|---|---:|---:|---:|
| CI 乐观端 | 79.7% | 94.3% | 100% |
| **点估计** | 44.7% | 75.3% | **92.7%** |

**选 R=4 是因为 92.7%,不是因为它便宜——它最贵。**
零假设一栏在三种 R 下都是 0.3%–2.3%,加图不会把误报率带回来。

**24 个 checkpoint 不在选项里**:`build_schedule` 的 `max_epochs=1` 使
`rounds × prompts_per_round ≤ 132`。把每轮 prompt 砍半能凑到 24 轮,
但那是 64 个 microbatch 摊到 6 张图上,训练的是记住六张图。**不是预算问题。**

## 2b. 并行化,以及它顺带暴露的一个真 bug

两臂的 evaluate + probe 链在评测期不共享任何东西(各自的 checkpoint、图目录、
manifest、日志、完成标记),原来却是串行跑的,一张 3090 在另一臂整个
generate-and-adjudicate 期间完全空闲。改成每臂固定一张卡(`ARM_DEVICE`),
`train` 不动(它本来就跨两卡:backbone 在 cuda:1、裁定阶梯在 cuda:0)。

**改完跑测试,现有的 supervisor 测试红了,查出来是真隐患:**
`write_json` 用固定的 `state.json.tmp`,而 `os.replace` 在 Windows 上
只要目标被任何句柄打开就报 WinError 5。三次试验对照实测:

| | 旧实现 | 新实现 |
|---|---:|---:|
| 写入失败 | **340 次** | 0–1 次 |
| 读到损坏 JSON | **8 次** | **0 次** |
| 遗留 tmp 文件 | **3 个** | **0 个** |

串行时写得少、只有外部读者偶尔撞上;并行后两个线程一起写,几乎必然踩中。
**而每次我去看 `state.json` 都可能让运行崩掉。** 修法两层:
tmp 文件名带线程 id(消除写-写互撞)+ 有限重试;
且 `state()` 吞掉 OSError——**它是遥测,不是证据**,
证据全部由各 stage 子进程和仍然会抛错的 `write_json` 调用写出。

另外把 stage 名字改成通过环境变量 `SELFSIGHT_STAGE` 传给子进程,
不再让子进程去读共享的 `state.json` 猜自己是谁。

新增 `tests/test_decoupling_supervisor.py` 10 项(并行确实重叠、
失败会上抛且不腰斩另一臂、每臂各一张卡、并发写不产生损坏文件)。
全部对照旧实现验证过会变红。

## 3. 明确不变的

- **划分。** `seed` / `local_outcome` / `local_probe` 与试点逐字节相同,
  `split_digest` 因此相同,**复用冻结的 2026-09-05 划分**。outcome 集是同一批 64 个 spec。
- **第一张图的 latent。** `evaluation_seed(candidate_index=0)` 仍然哈希原来那几个分量,
  所以本次 R=1 子集与试点曲线**逐字节可比**。
- **选择器。** 仍是 `observe_naive` → `fixed_atomic_score`。
  cycle 已过冻结门槛,但换它是 `2026-09-08-cycle-selector.md` §5 的改动,**未批准**。
- **内部曲线。** 只用每个 prompt 的第一张图,与试点同定义。
  多出的 3 张只服务外部曲线。内部曲线不缺检出力(斜率 +9.14/1000 步,SEM 0.09)。
- **裁定阶梯。** 同样两个检测器、同样的 verify,`candidate_index` 是语料池本来就有的字段。

## 4. 事先声明

- **本次仍可能给不出 D\*,而那不等于 D\* 不存在。** 任何「未找到」必须同时给出检出力。
- 折点前外部涨幅是三个旋钮里唯一不保证的。试点 32 步涨了 +7.4 / +6.5 pt,
  形状对,但**那是 5 个点的观察,不是承诺**。
- 单 seed,描述性轨迹,**不得写成显著性结论**。
- 语料的可利用边际只有 9/228 个 spec(`2026-09-08-cycle-selector.md` §7)。
  即使外部曲线动了,过优化也可能根本没有发生的空间。**这不是靠加图能改变的。**
