# 预注册：选择器的三段定义，与它必须先通过的分辨力检查

**写于 2026-09-04，在修改 `src/selfsight/v4/probe.py` 之前，也在看到任何新评分之前。**

动机：现行训练选择器**没有在选择**。232 个自然「有对有错」池上，naive 评分把
83.2% 的候选打成满分，60.3% 的池里四个候选完全同分，最高分唯一的池只有 8 个
（3.4%）。选中正确图的比例是 39.1%（K=4）与 34.0%（K=6），对应的均匀随机期望是
40.2% 与 34.2%——**两个独立子集上都贴着随机**。

这不是噪声，是天花板。原因写在构造里：**每道题的正确答案都等于 spec 要求的东西**，
所以一个不看图、只复述提示词的模型在每个候选上都拿满分。这是构造的数学后果，
与题目多少、难易无关。Gate B 的 `GDA-free` 余弦 0.9699（CI 宽 0.1285，未通过）与
它一致：不同准则挑出的几乎是同一批图，梯度自然指向同一个方向。

先写死，是因为 §12 记过一次赢家诅咒：判据在看过数之后被默认接受。这次不重蹈。

## 1. 选择器的三段，以及它们各自的 gold 从哪来

一张图「要求两个苹果、实际画了一个」，有两个都正确但不同的答案：

| 问什么 | 答案 | 来源 |
|---|---|---|
| 用户希望画什么 | 两个 | spec |
| 图里实际有什么 | 一个 | 图（裁定阶梯的检测） |

模型回答「一个」，说明它**看懂了图**；这张图仍然**没有完成生成要求**。

因此选择器必须拆成三段，且**观察准确率与生成符合度永不合并成一个分数**：

| 段 | 内容 | gold 来源 | 用途 |
|---|---|---|---|
| ① 要求的事实 | spec 要什么 | spec | 目标，不变 |
| ② 观察到的事实 | 模型看图后的**报告** | 图（用于给报告本身打分） | 衡量「有没有看」 |
| ③ 合成 | 把②的报告与①比对 | ①与②的关系 | **训练分数** |

**不采纳**「把随图变化的事实直接换进 `expected_answer`」的做法。那会把训练奖励改成
「看图回答准确」，从而奖励画错但容易识别的图片——研究对象被悄悄换掉。
③ 的比对仍然由 spec 决定，这一点保持现状是对的。

**拆掉饱和的那一刀落在 ②，不落在题量。** 约束是：**模型的回答必须无法从提示词复原。**
现行 `A. two / B. one` 的二选一，复述提示词就能答对；②ing 必须换成开放计数或高基数选项。
单纯增加容易回答的存在性题目不解决饱和，反而稀释有区分力的题。

已知的覆盖缺口（`probe.py` 现状，作为②要修的清单，不是全部）：

- 计数题只在 `obj.count > 1` 时构造 —— 「要一个杯子画了两个」没有任何题会问
- 计数题是 `wanted` vs `wanted-1` 的二选一 —— 要 2 画 5，答「two」照样算对
- 没有被要求的物体多画出来，没有任何题会问

**这三条是「规则没有检查该事实」，与「模型看了图仍然答错」是两件事，必须分开报告。**

## 2. 事先定死的分辨力判据

在**同一批 232 个 gate-b 池、同一批图**上重跑观察，只换②的题目与回答方式。
配对设计。判据分主次，**主判据不依赖平分规则**：

**主判据（池内分离）。** 在有对有错的池里，比较「正确候选均分」与「错误候选均分」：

| | 现行 | 参照（`questions.py` 带提示词，134 池） | **接受门槛** |
|---|---:|---:|---:|
| 正确 > 错误 的池 | 34.9% | 74.6% | **≥ 60%** |
| 正确 = 错误 的池 | 61.2% | 11.9% | **≤ 25%** |

**次判据。**

| | 现行 | 参照 | **接受门槛** |
|---|---:|---:|---:|
| 全部候选同分 | 60.3% | 11.2% | **≤ 25%** |
| 候选落在满分 | 83.2% | 58.6% | **≤ 70%** |

门槛取在现行与参照之间，不要求与参照持平：参照是**另一套题**（gold 随图变、
从检测构造），它衡量的是「这个模型在这批图上能达到多少分辨力」的上界锚点，
不是新的 spec 侧评分器必须复制的目标。n≈232 时 p=0.5 的标准误约 3.3 个百分点，
主判据要求的 +25 个百分点是它的 7 倍以上，不靠边界。

**相对随机选择的表现另报，不设门槛。** 选中正确图的比例与均匀随机期望一并报告，
带区间。**它是结果不是仪器检查**，拿它当门槛会让整件事变成循环论证。

## 3. 事先声明的失败模式

以下情况**不构成**改判据或改题目再试的理由，只构成如实报告的理由：

- 新评分器达不到主判据 → 记录未通过。**不得在看过数之后调题目直到通过。**
- 新评分器通过了分辨力检查，但选中正确图的比例仍然不优于随机
  → 这是**关于自评价选样的结果**，不是评分器的缺陷，不得据此再改评分器。
- 参照题集（`questions.py`）在任何指标上优于新的 spec 侧评分器
  → 预期之内，两者量的不是一回事，不构成改设计的理由。
- 新评分器在②上准确、在③上仍然选不出 → 说明观察准确与生成符合度确实分离，
  这本身是结论，按两个分数分别报告。

## 4. 本轮不做的事

D\*、D_g、梯度提前量、rerank/repair/posttrain 比较、机制消融、多模型扩展，
都不在这一轮。理由：它们全部在这个评分器下游，评分器没有分辨力时，
它们量到的是平分规则。

`§25 / §27 / §34` 的冻结预注册不因本文改动。已有实验记录保持原版本。

## 5. 重跑前的其他阻塞项（与评分无关，但同样必须先修）

**round-0 两臂权重污染。** `stage_train` 两臂共用一个 backbone，靠加载各自的
上一轮 checkpoint 切换，而 round 0 两边都没有上一轮：先训 naive 改了共享参数，
再训 rfo_gold 时**没有恢复基础权重**，gold 从 naive 训过的权重开始。配对设计
在第 0 轮就破了。见 `.planning/2026-09-04-project-audit/findings.md:211`。

**训练选样与内部评测分数不一致。** 训练按原子问答得分选图，内部曲线测描述恢复
概率。两者必须对应同一个选择规则，否则「内部曲线」不是选样在优化的那条曲线。

## 6. 这一步需要什么

定义、题目覆盖审计、已有数据复算、统计模拟：**CPU**。

**新题目的分辨力是否真的改善，必须让模型重新回答才知道；选择结果变了，
对应的梯度也要重算。改代码在 CPU 上完成，不代表实测不需要 GPU。**
