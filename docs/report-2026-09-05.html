01这个项目在问什么

一句话：模型正在用自己的理解能力给自己的生成打分，而我们不知道这个分数什么时候开始骗人。

现在的统一多模态模型（既能看图、又能画图的那一类）有一种很自然的自我改进方式：让它画一张图， 再让它自己看这张图、回答关于图的问题；答对了就说明画对了，于是把这张图当成好样本拿去训练自己。 这套做法已经被多个工作采用。

问题在于：「模型说它画对了」和「它真的画对了」是两件事。 如果模型在看图的时候还记得自己本来想画什么，它可能不是在读像素，而是在复述自己的意图。 一旦如此，这个自训练信号就会奖励「说得好听」而不是「画得对」，而且外部看不出来—— 因为内部分数一直在涨。

我们把这个失效叫做「效果脱钩」（记作 D*）： 训练继续把内部自评分推高，而外部可验证正确率不再同步提高、甚至开始下降的最早训练步。

难点不在于看出两条曲线分开，而在于把它跟两件长得很像的事分开： 普通收敛（两条曲线都到顶了，谁也没背叛谁）和随机波动（两条本来就在抖）。

真正需要这个结论的人恰恰没有外部真值可用——如果有真值，直接拿真值训练就好了。 所以项目的核心问题是：能不能在没有标签的情况下，提前预警脱钩即将发生。

关键设计是裁定阶梯：两个来自不同家族的冻结视觉模型各自回答原子事实问题（有没有这个物体、 几个、什么颜色），一致则采纳，不一致则送人工裁定。这样每一张图都有覆盖，而不是靠「两个模型一致」 去筛掉难判的图——被筛掉的恰恰是最需要判的那些。

两个外部模型始终是冻结的外部观察者，不是研究对象。 它们的输出不能当作「统一 backbone 能看见自己的画」的证据。

04已经拿到的硬结果：意图泄漏是真的，而且极大

同一个模型、同一批图、同一套题，唯一的差别是问题前面有没有那句「你是照这个描述画的：……」。

为什么这个反向很关键。图和描述一致时，那句描述略微帮忙；只有在像素与描述冲突时才崩塌。 加上描述之后有 221 道从对变错、只有 9 道从错变对。自我确认率（按被要求的场景而非画出的场景作答的比例， 随机 = 0.5）从 0.346 升到 0.664。

拆到最细的一格最说明问题：要求两个苹果、模型只画了一个，把描述放回上下文， 它 95% 的时候回答「两个」——它在断言一个自己没有画出来的物体存在。

还做了一个因果对照，排除了「编辑痕迹」这个解释

我们拿外部验证为正确的图，用修图的方式删掉其中一个物体，做成「图与描述冲突」的样本； 同时做一批 sham 对照：同一个填充器、同样大的面积、同一批图，但不删掉任何东西。

05两次预注册确证检验都没有通过 —— 如实记录

我们曾经有一个更细的假设，两轮新语料都没能确证它。它已被永久降级。

探索性阶段观察到：服从跟着「这是不是我会犯的错」走——如果生成器自己在别的种子上 漏画过这个物体，它在被问到时更容易顺着描述答。这个划分很有解释力，所以我们把它写成预注册， 在两批全新语料上各检验了一次。

06核心发现：训练用的选择器根本没有在选择

2026-09-04 查明。这是目前最重要的结果，它同时作废了好几个下游数字。

整个方法依赖一个动作：让模型给自己的多个候选图打分，挑出最好的那张去训练。 我们第一次直接去量这个动作的质量，结果是——它在随机猜。

原因不是模型笨，是判分规则的天花板

机制，在构造里一眼可见

每道题的正确答案都完全由用户的描述决定：问「有没有杯子」， 因为描述里要了杯子，答案永远是「有」；问「几个」，答案永远是描述里要的那个数。 于是一个根本不看图、只复述提示词的模型，在每一个候选上都能拿满分。 这是构造的数学后果，与题目多少、难易都无关——加题不解决它。

这作废了什么

  • Gate B 的失败有了解释，它的补救办法也随之失效。梯度仪器的一项判据（两条更新方向的 夹角余弦 0.9699，置信区间宽 0.1285 > 阈值 0.10）没有通过。原先注册的补救是「增加有区分度的池子直到区间收窄」—— 而有区分度的池子只有 8 个。补救办法要求的东西，正是缺的那个东西。 真正的原因是不同准则几乎挑出同一批图，梯度自然指向同一个方向。
  • 此前的「选择一致率 0.444」不能再引用——当时 60% 的池全部同分，那个数量的是平分规则。
  • 依赖「自评价选出了更好的图」的所有下游数字，在评分器修好之前，量到的都不是它们声称的东西。

而且，有一个方向相反的观察

①和③都建立在同一个符号上：意图泄漏会腐蚀基于自评价的选样。 在唯一一处能直接检验这个符号的地方，它是反的：

这是未预注册的事后比较，只能记为探索性观察：题集是从检测流程构造的（正确答案随图变化）， 与训练选样用的那套不同；四个 run 里只有两个有这个条件；平分规则是分析时才选的。

它不推翻第 4 节。第 4 节测的是泄漏让模型答题答错， 这里量的是选样。答题和选样是两件事，项目此前没有区分。 这条把「泄漏 ⇒ 选样变差」从可以引用的机制，降级为必须在训练开始前正面处理的待检验问题。

另外三个必须在重跑之前解决的问题

  1. 两臂第 0 轮起点不同。训练阶段共用一个 backbone，只在已存在 checkpoint 时才恢复权重， 因此第 0 轮的对照臂是从实验臂更新过的权重出发的。这是 bug，不是结果——不修，两臂的对比从第一轮起就不干净。
  2. 训练选样和内部评估用的不是同一套口径。脱钩就是这两条曲线的关系； 口径不一致时，它们的关系不是脱钩，是记账错误。
  3. 语料规模差约一个数量级。现有 228 条互不相同的描述，测脱钩需要约 1470 条。 修好评分器是必要条件，不是充分条件——之后还要扩语料并上更大的机器。

08接下来的五步

前四步一张 GPU 都不用起。顺序是刻意的：先把论证和判据定死，再动代码，最后才跑。

  1. 定义与判据 已完成
    把选择器拆成三段写清楚——用户要求的事实（来自描述）、从图像观察到的事实（来自图）、 以及二者如何合成训练分数；并在改评分器之前把分辨力、并列率、相对随机选择的表现写成预注册， 避免边修边挪门槛。同时把第 6 节的每个数字做成可复算脚本：记录变了或口径漂了，它拒绝出数。
  2. 改论证 已完成
    Proposal 改到 v3.5：①③降为待检验命题，D* 重定义为效果脱钩并写明要与普通收敛、随机波动分开， 预警时间与事后估计的折点拆开，删掉会把阴性结果变成阳性的兜底定义， 收窄两道门的结论范围，并把方向相反的那个观察正面写进去。只改论证，不改设计。
  3. 清掉三个阻塞项 纯静态诊断
    第 0 轮权重污染、训练/评估口径统一、以及一个尚未查清的显存异常。
  4. 改评分规则 CPU 可验证
    刀落在回答方式，不落在题量：现在是「A. 两个 / B. 一个」的二选一，复述提示词就能答对； 要换成开放计数或高基数选项，让答案无法从提示词复原。 但比对仍然由用户的描述决定——如果把随图变化的事实直接换成正确答案， 奖励就变成了「看图回答准确」，那会奖励画错但容易识别的图片，研究对象被悄悄换掉。
  5. 重跑 才需要 GPU
    在同一批池子、同一批图上重测，过了预注册的前置检查，才谈重跑训练。

还有几条一直在执行的硬约束：单 seed 的描述性轨迹不得写成显著性结论； 探索性观察不得当作结论引用；两个外部视觉模型始终是冻结的观察者，不得当作「模型能看见自己的画」的证据； 门判红之后不靠加算力、加 seed 或换 backbone 来抢救。

这次汇报本身就是这套自律的一个例子。 第 6 节的发现让项目退回到修仪器的阶段，也让 Proposal 里两条写成结论的主张退回成待检验问题。 这不是好消息，但它是在训练开销花出去之前发现的——如果按原先的写法开 Gate C， 一个仪器缺陷会被记成项目的失败条件。
