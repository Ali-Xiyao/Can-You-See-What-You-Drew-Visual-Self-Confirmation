Does the run record what each E3 endpoint needs? Checked, not assumed.

Endpoint 1 does. Endpoints 2 and 3 do not, and the reason is the same in both
cases: the per-checkpoint evaluation records one observation condition
(prompted) of one candidate (index 0) against one question set (spec-derived).
Endpoint 2 wants the other condition. Endpoint 3 wants the other condition,
the other three candidates, and the other question set.

Both gaps are recoverable offline -- the images and the per-round adapters
are saved and the backbone is the 1.5B -- so closing them is a re-observation
pass, not a retrain. This script measures the cost of that pass from
latencies already on disk rather than guessing it.

  images_drawn                 256
  candidates_drawn             [0, 1, 2, 3]
  candidates_self_reported     [0]
  self_reports                 64
  condition                    prompted only
  spec_questions_per_image     4.9375
  seconds_per_question         0.2464045854430379
  detector_questions_per_image 4.5   (from main-1plus1plus1)

==============================================================================
What each endpoint needs, and what it costs to get it
==============================================================================
pass                                                              min/unit  main 26   x5 130
endpoint 2  blind gap, candidate 0, spec questions                     1.3     0.6h     2.8h
endpoint 3  selection + conflict, 4 candidates, both conditions        9.4     4.1h    20.3h
both, one adapter load                                                10.7     4.6h    23.1h

  A unit is one (arm, checkpoint). 26 = 13 checkpoints x 2 arms for the
  main run; 130 = the same for five replicates. Adapter loads are on top,
  13 per arm, and the backbone stays resident across them.

  Against ~400 GPU-hours for the five replicates this is about 6%, and
  it is a 1.5B observer on one card -- so unlike the replicates it does
  not need both. Whether it fits beside the adjudication ladder on card 0
  is a VRAM question that has to be measured, not assumed.
