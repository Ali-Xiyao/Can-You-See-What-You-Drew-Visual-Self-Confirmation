# 回放消融 v1：新数据前冻结的开发实验

这轮检验共享理解回放是否解释固定图像上的否定回答塌陷和选择能力下降。不测自然生成 D*，不跑梯度，不恢复旧训练。旧实验停在 step32，所有新权重、日志和结果仅写本目录。已有 16 池是看过的开发集，主分析排除与训练场景重叠的 2 池，使用 14 池；不能据此宣布独立验证成功。

## 干预与比较

Naive 是主要被检验的训练路径。固定其旧实验实际选中的图片、逐轮顺序、每步 6 次生成微批次、初始化、学习率和 32 个优化步。四个回放条件：

1. original：旧回放的真实样本、顺序和目标。
2. zero_weight：同样的回放前向与反向，回放损失乘零；生成槽位和除数 8 不变。它是去掉回放梯度，不是增加生成训练。
3. balanced_absence：保留回放槽位、图片和题族，将每个题族约一半目标换成已核实不存在的类别，存在题答案 no，计数题答案 0。新增类别只取冻结词表、只能在已裁定正确的训练图片上，并再查逐物体记录确认非争议的不存在。其余正例保留；总回放预算不增加。
4. alternate_ids：每个槽位的题族和答案逐项匹配 original，换为其他样本 ID 和图片，排除本轮原始 64 个回放 ID、原始回放图片。固定另一个随机排序，不能看结果重抽。

另跑 Gold 路径的 original 与 alternate_ids。Gold-original 与 Naive-original 仍共享原始回放；两个 alternate_ids 使用不同的固定抽样种子。这样比较“共享内容分布下相同与不同样本实现”的行为一致率。单次替换不能证明一般的样本效应，也不能单凭输出一致证明梯度被回放主导。本轮不把 Gold-balanced 或多个随机种子追加进来。

6 次训练均从同一个已保存 base adapter 和优化器/调度器状态出发。使用原始 80 步计划的 8 步预热，最多训练至32步；不把预热缩短。真实历史生成样本被固定，因此这是离线训练干预，不是重新运行自适应选择/生成系统。

## 每步探针与最终测量

每次训练的 step0 及每个优化步测固定 100 个图像—问题条目，每条各测 prompt_on 与 prompt_off，共 200 答。条目在已知事实中按场景轮转抽取：25 个存在 yes、25 个存在 no、25 个计数正数、25 个计数 0。尽可能保留原请求类别缺失的条目；不足的 0 条目由已核实缺失类别生成。100 个条目不是100个独立场景。

分别输出 no/0 率、四个真值组的准确率、原存在题/新增否定题的细分、错误与弃答。每步探针仅监测：任一否定组准确率较 base 下降至少20pp并持续两个步，记录首次警报，不因此提前停止或调整训练。没有警报也不等于能力未受损。探针前后恢复 Python/NumPy/Torch/所有 CUDA RNG，保持模型原训练状态，禁止探针反传。

step0/16/32 在同一固定80张图上，用原题和原已冻结否定题，测 prompt_on、prompt_blank、prompt_off。主终点为 14 池、原评分、prompt_blank 的 top_correct_rate：对每池最高分集合均匀抽取的期望正确率；另报 prompt_off 和 prompt_on、基础率、实际选中正确率、并列集大小、事实准确率、请求匹配分。top_correct_rate 不是任意决胜器的上限。16池只作敏感性结果。所有池级变化配对，场景 bootstrap 5000 次；开发集、单种子、多个比较，CI仅描述。

## 结果判读（先写规则，再跑）

original 必须重现严重否定退化或固定图选择能力下降，才能用新干预解释旧现象；否则先报复现失败，查差异。新训练不保证参数逐位相同；记录真实权重摘要及与旧 checkpoint 的行为差异。

“否定修复”操作性标准：step32 两个否定组准确率各距自身 base 不超过10pp，且两个正例组准确率也各距 base 不超过10pp，两种提示条件分别报告。它是开发诊断阈值，不是独立群体验收。

- 若修复达标而选择下降仍明确存在（step32-base 的配对95%区间上端低于 -5pp），仅说明此干预未解释全部退化，列为待独立验证现象；不能直接称与否定能力无关。
- 若修复达标，选择变化的90%区间完全在 ±5pp 内，才称本开发集的下降消失。撤回把旧下降泛化为目标 D* 的解释；旧记录保留。
- 若下降点估计减弱但仍负，报效应及区间，不要求单调，也不自动宣布机制成立。
- 修复不达标、original不复现、区间太宽，或方向不一致：报告该问题尚无定论。无显著差异不等于消失。

参数摘要、原始回答、逐微批次损失/样本ID、RNG保护记录和数据哈希均保留。最多6×32优化步；原预算截止前或新控制器启动后6小时硬停；任何错误不自动重启。两张卡各单进程，持有原 supervisor 锁，确认旧 round004 不存在。不得为寻找显著结果延长训练。
