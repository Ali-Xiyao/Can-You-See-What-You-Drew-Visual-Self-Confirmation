## 1. 取代了什么,依据是什么

| 冻结条目 | 内容 | 取代范围 | 依据 |
|---|---|---|---|
| §25 | §24(b) 服从分界的确证检验 | **不取代**。已由 §26 / §35 判定为不确证,§24(b) 永久降为探索性。本文件不碰它 | — |
| §27 | 第三批语料按实测效应量重新定 n | **不取代**。同上,已执行完毕并已判定 | — |
| §34 | L3 预告的停止规则(围绕 D\*) | **取代其终态定义**:论文的主张不再依赖 D\* 或 Lead | 见下 |

**§34 被取代的具体理由**(全部可复算,见 `review-packets/dg-power-20260908/`):

1. `Lead = D* − D_g` 是**两个搜索出来的拐点之差**,SE 16–18 步,而整个训练跨度
   只有 88 步。要让它显著,真实 Lead 得大于约 35 步。
2. 这个 SE **不能靠加 checkpoint 救**:12→24→48 个 checkpoint,拐点 SD 只从
   11.4 走到 11.0 再到 7.2。噪声在曲线本身,不在采样密度。
3. 已注册的 `paired_bootstrap_lead` 是**反保守的**(实测 type-I 9.5%),
   而它报的「95% CI」实际上只是 3 个 seed 的 lead 极差。
4. D_g 的出厂估计量在真实数据上**从未跑通过**:缺 `gda_*` / `noise_*` 列、
   缺 `seed` 列、缺 `gradient_probe.ema_alpha`。原先记录的 0/2000 误报率是**模拟**的。

**结论**:拐点类估计量(searched knot,SD 11.3 步)与比例类估计量
(SEM 0.0150)差一个数量级。论文改用后者。
D\* / D_g / Lead **降为附录里的仪器负结果**,原始记录保留,不删。

## 2. 论文主张(一句话)

**在统一模型里,验证者与生成者共享权重,而且验证时生成 prompt 还留在上下文里,
所以它不是独立验证者,是一个 prompt 条件下的确认器。把 prompt 移出上下文
(BSV)是零训练成本的修复。**

## E3. 主实验:三臂协同进化(预注册)

### 设计

| arm | 选择信号 | 来源 |
|---|---|---|
| A `naive` | prompt 在上下文里 | `runs/v4/decoupling-main-20260908`(在跑) |
| B `blind_self` | prompt 移出上下文 | **待跑** |
| C `rfo_gold` | 外部 gold | 同 A 的运行(在跑) |

**arm B 的运行方式已定,写在这里以免事后可选:**
新建输出目录,用**同一份 config**(`configs/v4_decoupling_main_20260908.yaml`),
跑 `--arms naive blind_self`,即 **B 与一列新的 A 在同一次运行里配对**。

理由(pilot 实测,`rounds/round-*/selection.json`):`naive` 12/12 从不弃权,
`rfo_gold` 只选 7–9/12。`pair_decisions` 取交集,所以**主运行的 A 列实际只在
约 75% 的 prompt 上训练**。若 B 单臂跑,它会在 100% 上训练,A–B 对比就带上
prompt 集混淆——而 A vs B 正是本文的主张所在。
split 会自动一致:`split_prompts` 是 (prompt_ids, outcome, probe, seed) 的纯函数,
同 config 必然复现同一份划分,digest 校验会确认。

主运行里的 A 列因此成为**独立复制**,不是唯一比较对象。

### 端点 1(主):最终外部正确率

**假设(方向已定,单侧)**:B > A。

**统计**:同一批 outcome prompt、同一批固定 latent,逐 (prompt, draw) 配对。
64 outcome prompt × R=4 draw = 每 checkpoint 每臂 256 张。
配对比例差,bootstrap over prompt(不是 over image——同 prompt 的 4 draw 不独立),
20000 次重采样,报 95% CI 与配对精确 McNemar。

**功效**:已实测配对比例差的 SEM ≈ 0.0150(`review-packets/dg-power-20260908/lead_resolution.py`)。
80% 功效可测到约 **+0.042** 的差。**这个数字在看结果之前写下**:
若 B−A 的点估计小于 0.042 且 CI 含 0,判为**未测到**,不得改口径抢救。

### 端点 2(主):协同——逐 checkpoint 的盲测判别 gap

对每个 checkpoint,在**盲**条件下计算 s_select 对
「实际正确」与「实际错误」候选的判别 gap(即
`review-packets/dg-power-20260908/prompt_recital.py` 的口径,但去掉 preamble)。

**假设**:A 的 gap 随训练塌向 0(pilot 已观测:+0.047 → 0.000,32 步内,两臂皆然),
B 的 gap 不塌。

**判定**:对每个臂做 gap 对 step 的 OLS 斜率,配对 bootstrap over prompt。
**确证条件**:A 的斜率显著为负,且 B 的斜率显著大于 A 的斜率。
只有 A 塌而 B 也塌 → 判为「BSV 不能阻止感知被吃掉」,如实写。

### 端点 3(次要,预注册):剂量-反应

离线重放发现两个 corpus 的选择增益差 5 倍(+0.190 vs +0.034),
而**来源在确认偏差本身的强度**:冲突试次上的上下文效应
−0.440 vs −0.214,盲侧几乎不动(0.638 / 0.667)。

**预注册的预测**:把主运行的每个 (arm, checkpoint) 当一个点
(13 checkpoint × 2 臂 = 26 点),横轴 = 该 checkpoint 的上下文效应强度
(冲突试次上 blind 减 prompted 的准确率),纵轴 = 该 checkpoint 的选择增益
(盲选相对带 prompt 选的外部正确率之差)。
**预测斜率 > 0**,cluster bootstrap over checkpoint。

若斜率不显著为正:异质性在论文里写成**未解释的调节效应**,不得说成剂量-反应。

### 预先声明的失败条件(任一成立即降级,不抢救)

1. 端点 1 未测到 → 论文不得声称「BSV 提升生成」,只能声称
   「BSV 提升选择信号质量」(离线重放已支持),主张收缩到推理期。
2. 端点 2 里 B 也塌 → §2 的机制解释被证伪,必须在正文写明。
3. arm B 的 `blind()` 守卫抛错 → 说明题目里混进了 prompt,该轮作废重跑,
   **不得**关掉守卫。
4. 墙钟超过 60 h,或同一阶段连续两次不可恢复失败 → 停,登记 traceback。

**不构成停止理由**:结果是 null;曲线难看;别人的作业占卡(等就行)。

**无论结果如何都不做**:不加 seed / 不加算力 / 不换 backbone 去抢救;
单 seed 轨迹不写成显著性结论;不回头改本文件。

## 偏离 3(2026-09-08,E4 仍无任何模型作答;评分器本身有缺陷)

E4 要用 §1 的题目去问四个模型,但**写这些题的评分器只在一个模型上校准过**。
Show-o2-1.5B 在 7246 条冻结行里全部只回一个裸字母,`grade` 因此只有两条规则,
两条都在会写句子的模型上失效,而且**都是静默失效**:

| 回复 | 旧 `grade` | 实际说的 |
|---|---|---|
| `Answer: B` | A | B |
| `Based on the image, it is the plate` | B | A(plate) |
| `The answer is A because ...` | 弃权 | A |

前两条比丢一个试次更糟:**模型给了正确答案,记录里却是一个它没给过的错误答案**。
`ANSWER` 以 A 开头、`Based` 以 B 开头,而 `startswith` 分不出「选中的字母」
和「一个词的首字母」。第三条把试次从分母里拿掉,而**哪些试次被拿掉,取决于
模型想说多少话——这跟 E4 变动的那个条件并不独立**。

**改了三处**(worktree `codex/blind-self-arm-20260908` 提交 99b7c0f):

1. `BARE_LETTER`:字母后面必须是标点或回复结尾。冻结回复只有三种形状
   (`A` / `A.` / `B. left`),三种全部照旧命中;以 A/B 开头的**单词**、
   以及英文不定冠词 `A plate ...`,全部不再被当成选择。
2. `LABELLED_CHOICE`:读 `Answer:` / `Option` / `Choice` / `The answer is`
   后面的字母,中间的标点(含 `**Answer:**` 的星号)跳过。
   **必须有标记词**:早先一版接受「结尾的裸字母」,把一条截断在
   `possibly a lemon or a` 的 Janus 回复变成了一个自信且碰巧正确的 A。
3. `official_profile.mmu_max_new_tokens` 真正被读进适配器:Janus 64,其余 16。
   16 个 token 不够它把句子说完,字母还没出现回复就被截断了。

**已经测出来的数字一个都没有动。** 用改后的代码重新评 `main-2plus1` 与
`main-1plus1plus1` 的全部 7246 条回答,每一条都复现出那两个文件里原本写着的
`correct` 字段;其中 52 条含标记词,所以新规则确实被走到了,「没有变化」
才是有信息的。这条在 `tests/test_v4_spec_questions.py` 里是一个会跑真实数据的
测试,不是一句声明。**§1 的冻结记录原样保留,未重算、未改写。**

新规则的六个变异里五个被新测试抓红;活下来的那个是标记词前面的 `\b`,
没有任何现实回复能区分它。

**对 E4 判定的影响**:token 预算是**每个模型一个值、两个条件相同**,
所以它不能移动 E4 读的那个模型内对比;评分规则对四个模型完全相同。

## 偏离 4(2026-09-08,E4 仍无任何模型作答;预检门本身选错了图)

偏离 2 说预检已在 CPU 上过了。**那次通过是偶然的,门本身是坏的。**

预检问一个问题——「What colour is the largest object? Answer with one word.」
——问若干张图,要求答案彼此不同;答案全同就判「图没有到达语言塔」。
它取的是 `sorted(glob("*.png"))[:count]`,而语料把同一个 prompt 的多个采样

### 7.1 问题:单 seed 怎么补,以及 scaling 为什么补不了

- **加 seed**:偏离 6.2 已经算过,n=2 的方差估计 df=1,要 5 个以上,380–440 h。
- **scaling**(更大的模型 / 更多数据):它回答的是外部效度(「更大的模型上还成
  不成立」),不是 run-to-run 方差;而且模型越大每个 seed 越贵,**它把这个问题
  变严重而不是变轻**。规模这条轴 §E4 已经覆盖,且只覆盖推理期那一半。

正确方向是**换被复制的对象**,不是买更多算力。设计里已经有三条零成本的复制轴,

### 7.2 登记:A 与 A' 的漂移,作为 run-to-run 噪声的上界

主运行跑 `naive` + `rfo_gold`,arm B 的运行跑 `naive` + `blind_self`,
**`naive` 因此被独立地跑了两次**(§E3 已把它称作「独立复制」)。arm B 那次运行
本来就要跑,所以本条的边际算力成本是零。

记主运行的 A 列为 θ_A、arm B 运行里的 A 列为 θ_A'、arm B 为 θ_B,
全部取端点 1 的口径(最终外部正确率,同一批 outcome prompt、同一批固定 latent)。
两次运行的 split 相同(同 config,digest 校验会确认),所以这个差是在**同一批
评测题**上算的——训练子集不同是另一回事,见下。

`|θ_A − θ_A'|` 里装着两样东西:run-to-run 漂移,**加上**配对差异(主运行的 A 与
`rfo_gold` 取交集、约 75% 的 prompt 上训练;arm B 里的 A 与 `blind_self` 取交集,
是另一个子集)。两个 A 看过不同的训练数据,**所以它不是干净的 seed 复制,
它是一个上界**——而上界正是这里需要的方向。

- `|θ_A − θ_A'| < θ_B − θ_A'` → 观测到的 A–B 差异**大于**一个连配对差异都算进去
  的 run 级漂移上界。这不证明「与 seed 无关」,但它是在这条流水线上实测的、
  方向保守的证据,可以写进正文。
- `|θ_A − θ_A'| ≥ θ_B − θ_A'` → **训练期主张与 run 级漂移不可分离**,正文必须
  这样写,主张收缩到推理期。**不得**改口径、不得只报有利的那一半、不得改口说
  「两个 A 配对不同所以不可比」——那个不可比性在写下本条的这一刻就已经知道了。

**适用范围:本条只在端点 1 判为「测到」时起作用。** 端点 1 未测到时,失败条件 1

### 8.4 n=3 的正确用法(事前写死)

1. **三条轨迹各自单独报出来**(逐 checkpoint 的外部正确率曲线,每个 seed 一条)。

3. **唯一的正式检验**:prompt 级配对为主体,seed 进随机截距——

- `v4_train.py` 全部用顶层 `config["seed"]`,而它同时决定三样东西:
  **split**(`split_digest` = sha256 over {runs, seed, data.local_outcome,
  data.local_probe})、**LoRA 初始化 / 训练 RNG**(`seed_training`)、
  **评测 latent**(`evaluation_seed`)。

所以直接把顶层 `seed` 改三次,得到的是三次**在不同数据划分、不同 64 个 outcome
spec、不同固定 latent 上**的运行:配对全废,还丢掉 2026-09-05 的冻结划分,

### 9.2 n=5 与 n=3 的真实差别:seed 层面第一次有了一个能过的检验

### 9.3 seed 层面的确证检验(事前写死,取代 8.4 第 2 条)

- 4/5 同向 → p = 0.1875,**未确证**。如实写,不得改成双侧、不得换检验、

- `d_s` 恰好为 0 的 seed:**计入分母、按保守方向计为不支持**,不丢弃。

## 偏离 10:端点 1 的配对里,未裁决的图怎么处理(2026-09-09,写在最终分析脚本之前)

### 10.0 先声明我看过什么

写本条之前我已经读过主运行 `evaluations/naive/step-00008/verified.summary.json`,
看到过 `n=256`、`pending_human=17`、以及那一格的 `p`。当时
`checkpoint_metrics.csv` 已经写出(09-09 08:20),EXECUTION §4 那条
「写出之前不看任何数值」的前提已经解除,所以看本身合规。
**但本条要定的规则会作用在那些数上**,所以按 §0 的利益冲突口径,
先把「我已经看过一格 arm A 的聚合正确率」写在这里,再定规则。
定规则时没有看过任何 arm 之间的差,也没有看过 `blind_self` 的任何数。

### 10.1 问题

`verified.jsonl` 的 `resolution` 有四种,其中 `pending_human` 与 `unnameable`
是**未裁决**。仪器侧的既有约定三处一致
(`src/selfsight/v4/evaluate.py` 的 `UNADJUDICATED`、`external_correctness`、
`scripts/v4_decoupling_report.py`):**未裁决的图从正确率的分母里剔除,
不算错**。理由写在 `external_correctness` 的 docstring 里,本条不动它。

但那三处都是**单臂**的描述性口径。端点 1 注册的是
「逐 (prompt, draw) 配对 …… 配对精确 McNemar」,而配对分析会撞上一个
单臂口径从来没遇到过的情形:**同一个 (prompt, draw) 在 A 臂已裁决、
在 B 臂 `pending_human`**。按臂各自剔除会让两臂的分母落在不同的图上,
配对就名存实亡,McNemar 更是无从谈起。

### 10.2 规则(事前定死)

1. **成对剔除,单位是 (prompt, draw)。** 某个 (prompt, draw) 只要在**任一臂**
   未裁决,该 pair 在**两臂**同时剔除。端点 1 的所有量——点估计、
   bootstrap、McNemar——都只在两臂皆裁决的 pair 上算。
2. **prompt 级 bootstrap 的重采样单位不变**,仍是 prompt。剔除之后某个 prompt
   剩几个 draw 就用几个,该 prompt 的贡献是其存活 draw 上的均值。
3. **一个 prompt 的 4 个 draw 全被剔除**,该 prompt 在该 checkpoint 退出 prompt 池;
   bootstrap 的池大小随之变小,**不做补齐、不做插补**。
4. **必报的覆盖率**:每个 (seed, checkpoint) 报 `n_pairs_kept / 256`、
   退出的 prompt 数,以及两臂各自的未裁决数。**任一 checkpoint 的
   `n_pairs_kept < 192`(75%)时,该 checkpoint 在正文标注低覆盖**,
   但仍照常进入分析——阈值是用来触发披露的,不是用来剔数据的。
5. **两臂的未裁决率不对称本身要报。** 若某一臂系统性地更常 `pending_human`,
   那是一个关于该臂产图质量的发现,不是噪声;它必须出现在正文,
   不能只活在被剔掉的那部分里。

### 10.3 为什么是成对剔除而不是别的

三个候选,只有一个和已注册的端点自洽:

| 做法 | 与端点 1 注册文字的关系 |
|---|---|
| 按臂各自剔除(available-case)| 两臂分母落在不同图上,**配对失效**,McNemar 不成立 |
| 未裁决计为错 | 与仪器侧三处既有约定冲突,且 `external_correctness` 的 docstring 已论证它会把断点系统性地拉早——**正是假设预测的方向** |
| **成对剔除** | 保住「逐 (prompt, draw) 配对」与「配对精确 McNemar」两句注册文字 |

所以这不是一个新的自由度,是被已注册的端点定义**逼出来的唯一解**。
本条把它写下来,只是为了它不要在写代码的时候被默默选掉。

### 12.1 问题

4. **仍然抛异常的情况**:两臂的 **manifest** key 集不同。

  没找到,这条路径上没有任何东西能排除;把它计为错就是把仪器噪声算进效应。

### 13.1 端点 2:把「配对 bootstrap over prompt」写成可执行的

注册原文:「对每个臂做 gap 对 step 的 OLS 斜率,配对 bootstrap over prompt。
**确证条件**:A 的斜率显著为负,且 B 的斜率显著大于 A 的斜率。」
下面七条是它落到代码时必须定死、而原文没说的:

1. **重采样单位与配对方式**。一次重采样 = 从该 seed 的 prompt 集合里有放回抽同样多个;
   **同一份重采样后的 prompt 多重集,同时用于两个臂的每一个 checkpoint**,
   然后各自重算每个 checkpoint 的 gap、各自重拟 OLS 斜率,记下
   `slope_A`、`slope_B`、`slope_B − slope_A`。
   「配对」指的是**跨臂**配对:在一个 checkpoint 内,一个 prompt 要么在 right 侧
   要么在 wrong 侧,不可能和自己配对,所以配对只能发生在臂之间。
2. **「显著」的操作定义**。
   「A 的斜率显著为负」= A 的 bootstrap 斜率分布的 **97.5 分位 < 0**;
   「B 的斜率显著大于 A」= `slope_B − slope_A` 分布的 **2.5 分位 > 0**。
   都是 95% 百分位区间的单侧读法,和端点 1 读区间的方式一致。
3. **常数**。20000 次、种子 20260908。理由要写明:偏离 6.4 把 bootstrap 拆成
   「在跑的 report(2000 / 20260906)」与「最终分析(20000 / 20260908)」两支,
   端点 2 的确证拟合是最终分析,走后一支。**这是一个阅读,不是一个假设**,
   所以登记在这里而不是默默继承。
4. **退化重采样**。某次重采样里,若某个 checkpoint 的 right 侧或 wrong 侧为空,
   该 checkpoint 的 gap 无定义:**把该 checkpoint 从这一次重采样的拟合里剔除**;
   若存活的 checkpoint 少于 3 个,整次重采样作废。两个计数都要报。
   (64 个 prompt、约三分之一为 right 时这两件事的概率都在 1e-11 量级——
   这是护栏,不是政策,写下来是为了它不会变成一个 NaN。)
5. **横轴是 `step`**,不是 checkpoint 序号。两者等距,对显著性没有差别;
   定死它只是为了少一个自由度。
6. **用哪些 checkpoint**。用两臂盲测都完成的那些。若有缺,
   **照实报「在 N 个 checkpoint 上拟合」并列出缺的**,不得默默拟合一条更短的序列。
7. **偏离 9.4 的 4/5 怎么算**。每个 seed 内部按第 2 条判「A 的斜率显著为负」,
   5 个 seed 里 ≥4 个成立算这一半成立;另一半是对 5 个
   `slope_B − slope_A` 做单侧精确符号检验。两半都要成立。
   **禁止**对这 5 个差值做 bootstrap(偏离 9.3 的同一条理由)。

只报两列的话,「严口径下剂量-反应还在不在」这个问题在输出里没有答案。

**定死**:斜率在两种口径上**各拟合一次、各报一次区间**,
用同一份嵌套重采样(偏离 13.2 第 5 条),同一个种子。

**判定只看期望值那一支**——§3 写的是「为主」。首索引那一支是稳健性对照,
**不参与判定、不改判定条件、不改注册预测**。两支方向不一致时,
正文必须写明不一致,不得只报一致的那一支。

### 15.4 失败条件 3 与 4:仪器比注册更严,登记,不改

清查顺带核了另外两条,它们**有**代码,但代码比注册**更严**:

- **失败条件 3**(`blind()` 守卫抛错 → 该轮作废重跑,不得关掉守卫):
  守卫在 `selfsight.v4.observe.blind` 里,抛 `ValueError`
  (`staging/arm-b-merged` 上有四个测试钉着它,含换行重排后的泄漏)。
  但抛错时那一阶段以非零退出,supervisor 走
  `RuntimeError(f"{stage} failed with exit ...")` **停机**,
  不是「该轮作废重跑」。
- **失败条件 4** 后半(同一阶段**连续两次**不可恢复失败 → 停):
  supervisor 没有重试,**一次就停**。

两处都在保守方向:只会多花墙钟,不会造出一个结果。
**不改仪器**,理由有二:(一) 主运行在跑,改在跑的 supervisor 是硬禁;
(二) 更严的那一侧不需要救。登记在这里,是为了将来不会有人把它「修」成
注册的那个较松版本,也为了正文不去声称一套本项目没有的重试策略。
